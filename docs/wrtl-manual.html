01 · O que é WRTL?

WMK Racing Track Language é um formato declarativo baseado em JSON. Descreve uma pista, não executa código. O motor Extreme lê os dados e gera uma spline fechada, referenciais móveis e malhas 3D. Há 16 tipos predefinidos e um tipo custom. O formato atual não é uma linguagem modular de encaixe de peças.

Fluxo: descrição → Ollama/Groq → JSON → normalização → validação → motor Extreme → teste humano → exemplo aprovado.

Primeiro teste

  1. Na raiz do projeto execute python ai/server.py.
  2. Abra http://127.0.0.1:8768/ai/.
  3. Abra Projeto WRTL pelo menu Painéis; cole o exemplo abaixo.
  4. Clique Validar e visualizar. Em Testes, escolha Vista geral ou Pilotar; clique na viewport e use W/S/A/D.
  5. Exporte o JSON para reutilizar no jogo Extreme.
{
  "name": "Inferno 7000",
  "type": "double",
  "radius": 45,
  "scale": 1.2,
  "width": 20,
  "bank": 0,
  "accent": 16711680
}

Este procedimento manual não exige uma chamada à IA. O motor usa Three.js carregado externamente; o navegador pode precisar de internet.

02 · Sintaxe e contrato

Um único objeto JSON, chaves e strings entre aspas duplas, números sem aspas, sem comentários ou vírgula final. Os sete campos são obrigatórios inclusive quando um parâmetro não afeta a geometria escolhida.

CampoTipo e limiteFunção
namestring de 1 a 80 caracteresNome não vazio
typeenumTipo do catálogo
radiusnúmero 15–55Raio base em metros, usado em loop/double
scalenúmero 0,7–1,5Multiplicador XYZ da trajetória; não altera width
widthnúmero 8–40Largura em metros; diâmetro em mototube
banknúmero 0–80Inclinação em graus nos tipos compatíveis
accentinteiro 0–16777215Cor RGB decimal
pointsarray de 4–320 triplasObrigatório apenas em custom
twistsinteiro −8 a 8Opcional em custom; padrão zero

Não inclua points ou twists em presets. O normalizador de IA remove ambos e informa a alteração. Na revisão atual, o validador JS manual rejeita points em presets, mas ainda aceita twists dentro do limite; o motor não usa esse campo nos presets. O contrato formal proíbe os dois.

Em bowl o banking é aplicado como 55% do valor informado, além da seção côncava. Em helix e mototower o raio da trajetória é fixado pelo algoritmo; radius não altera esses tipos. Em wall e custom a inclinação varia senoidalmente; em sky, wave, helix, figure8 e mototower também varia ao longo da volta.

04 · Coordenadas XYZ

X e Z são horizontais; Y é altura. Cada ponto contém três números em metros antes da escala, entre −1500 e 1500; Y deve ser no mínimo 2. A distância entre pontos consecutivos, incluindo último e primeiro, deve ser no mínimo 0,5 m. Não repita o primeiro ponto no final. O motor fecha a spline automaticamente. Recomenda-se 6–40 pontos inicialmente, distribuídos em torno de uma área, sem pontos colineares.

{
  "name": "WRTL custom",
  "type": "custom",
  "radius": 35,
  "scale": 1,
  "width": 16,
  "bank": 45,
  "accent": 65535,
  "twists": 1,
  "points": [
    [
      0,
      5,
      -120
    ],
    [
      0,
      20,
      0
    ],
    [
      0,
      45,
      120
    ],
    [
      120,
      55,
      150
    ],
    [
      200,
      20,
      0
    ],
    [
      120,
      5,
      -150
    ]
  ]
}

twists=1 gira a normal uma volta completa ao longo do circuito; −1 inverte o sentido. Não significa acrescentar um looping vertical. A geometria custom é uma fita, não um túnel circular.

Matemática

O motor usa CatmullRomCurve3 centrípeta fechada; amostragem por comprimento de arco; tangente T, normal N e lateral R=N×T; quaternions transportam a normal. Para loop, Y=3+R(1−cos θ) antes da escala. Um raio 45 com escala 1,2 produz desnível nominal de 108 m. A spline pode alterar levemente as dimensões.

07 · Como ensinar Qwen e Groq

Ollama: qwen3:1.7b. Use Preset para tarefas simples; o servidor envia schema sem points/twists. Use Coordenadas XYZ para custom. Groq: openai/gpt-oss-20b, configurando GROQ_API_KEY no ambiente do terminal antes de iniciar o servidor. Não coloque chaves no JSON nem no painel de conhecimento.

Prompt recomendado

Modo preset. Crie uma pista chamada Inferno 7000 com dois loopings, raio base 45 m, escala 1.2, largura 20 m e neon vermelho. Use type double e accent 16711680. Retorne apenas os sete campos obrigatórios.

Para testar a compreensão sem entregar a resposta, use o mesmo pedido sem informar type e accent. Compare os resultados no painel Testes. No console, observe a resposta original antes da normalização. Se necessário, corrija o JSON, valide, teste e clique Ensinar com JSON validado no painel Conhecimento Qwen. Até cinco exemplos são enviados como contexto; instruções locais também podem ser salvas. Isso é few-shot prompting, não retreinamento.

Experimento controlado

  1. Prepare Looping duplo vermelho.
  2. Gere com Qwen e registre tempo, campos divergentes e correções.
  3. Corrija e aprove o exemplo.
  4. Repita com um pedido diferente, por exemplo raio 30 e neon azul, para verificar generalização.
  5. Repita com Groq e compare, sem assumir que um modelo é sempre superior.

O modo JSON do Groq não garante conformidade integral com o schema. O schema do Ollama restringe a forma, mas não garante fidelidade ao pedido.

08 · Diagnóstico

ProblemaCorreção
points é exclusivo do tipo customRemova points/twists do preset ou use custom com pontos adequados.
Campo desconhecidoRemova chaves não documentadas, inclusive version, segments e gravity.
Pontos consecutivos muito próximosSepare os pontos; não repita o primeiro no final.
Cor diferenteCorrija accent; normalização não interpreta intenção.
Resposta vazia / HTTPUse servidor Python na porta 8768; confira o console e o provedor.
JSON válido mas pista ruimInspecione a vista geral, teste uma volta e ajuste os pontos. Validação estrutural não detecta toda auto-interseção ou colinearidade.

Limitações atuais

Física magnética cinemática, sem forças reais; não existe composição arbitrária de segmentos, saltos balísticos Extreme, verificação geométrica completa ou RAG. A conversão de tubo em custom perde seção circular.

09 · Exercícios e evolução

  1. Altere a largura e cor de double; teste a diferença.
  2. Compare radius 20 e 45 em loop.
  3. Crie mototube com diâmetro 24 e pilote no teto.
  4. Crie custom com oito pontos e duas torções.
  5. Provoque um erro com points em double, depois normalize.
  6. Compare Qwen e Groq em três pedidos inéditos.

Versões futuras propostas: WRTL 0.2 com módulos encaixáveis e compilador; 0.3 com objetos interativos e diagnóstico geométrico; 0.4 com receitas reutilizáveis. Os números são planejamento, não funcionalidades disponíveis. A versão da linguagem é independente da versão do jogo.

Ao alterar o contrato, atualizar schema, validador, motor, knowledge.txt, exemplos, testes e este manual juntos. Registrar mudanças no histórico WRTL. Preservar exemplos antigos ou fornecer migração.
